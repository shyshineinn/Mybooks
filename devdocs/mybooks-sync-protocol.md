# 单用户、多设备同步（协议 2）

这批改动为书目增加 `revision`，以 UUID 标识同一本书，保持单管理员、多设备授权。
它仍是完整同步视图；增量游标、多人权限和阅读位置的服务端同步不在本批范围内。

## 删除保护

`GET /api/sync/books` 返回 `sync_version: 2`、`complete: true`、`library_id`、
全部在架书 `books` 和明确的删除记录 `deleted`，不接受筛选或分页参数。
缺少书目、空数组或网络失败都不是删除指令。
客户端校验整个响应后才处理事件；书目 id、UUID、版本必须有效且互不矛盾。

删除记录随软删除、硬删除和合并在数据库事务中保存，回收站到期也不会清掉。
从回收站恢复书籍时取消其删除记录，并推进版本。
安卓收到删除记录后标记“服务器已删除”，保留本机文件、阅读进度、标注和待上传修改。
服务端恢复同一本书后，下一次同步恢复关联。

安卓排队删除包含操作时的 UUID 和版本；服务器已被别处修改时返回 409，停止删除。
旧队列缺少原版本时，需要在“同步问题”中取消后重新核对书目。
旧后端没有协议 2 时，新客户端继续拉取书目，但不向它发送排队删除。

## 并发修改

新版 PATCH、PUT、DELETE 支持 `expected_revision` 与 `expected_uuid`。
版本或身份不匹配返回 409 和 `current`；原有 `expected_updated_at` 继续兼容旧客户端。
书目、附属文件、标识符、自定义字段值等变更都会推进书目版本。
网页编辑表单提交打开表单时的版本，冲突时保留表单内容并提示。

安卓同一字段双方都修改时，不再比较手机时钟决定覆盖。
冲突及本地修改持久保存，可在「设置 → 服务 → My books 服务器 → 同步问题」处理：

- 保留本机修改：基于最新服务器版本重新提交本机修改，继续执行版本条件检查。
- 采用服务器版本：放弃本书待上传的元数据修改；阅读进度与标注保留。

回包只能确认它实际提交过的内容，同步期间产生的新编辑继续排队。
书目回填使用独立的元数据更新语句，不覆盖本地正文路径、阅读位置或下载状态。
书库身份变化、书目身份不匹配或版本倒退时停止自动更新，保留本机数据。

## 升级与验收

后端数据库迁移为 v16，安卓 Room 为 v22。上线前备份数据库与附件，并保留旧代码版本。
建议先更新后端，再更新安卓端，并刷新网页资源。
旧安卓仍可访问新版后端，但只有新版客户端具备本批同步保护。
回退程序时应恢复与其结构版本匹配的数据库备份，不能直接让旧安卓打开 v22 数据库。

重点验收：离线编辑与重启、两端同时编辑、回收站删除与恢复、硬删除后长期离线同步、
同步请求期间继续编辑、旧版本删除被拒绝，以及本地阅读位置不被书目更新覆盖。
